Privacy Policy. AltGenie.

Last updated: 2026-07-21

Summary

AltGenie runs entirely on your device. It does not collect, transmit, or sell personal data. The extension reads images on the web pages you visit only when you explicitly right-click an image to request alt text, or when you opt in to the passive auto-audit badge. All generation happens via Chrome's built-in on-device Prompt API (LanguageModel) — the image bytes never leave the browser process. All settings stay on this device in Chrome extension storage.

Permissions and why each one is required

  • contextMenus. Registers the "Generate alt text (AltGenie)" item on contexts: ['image']. Your right-click is the explicit gesture that authorizes the single-image processing flow.
  • activeTab. Granted on user gesture (right-click, badge click, or popup toggle); authorizes chrome.scripting.executeScript for the page audit and the write-alt call. Does NOT require host_permissions.
  • scripting. Enables chrome.scripting.executeScript for (a) the audit pass that walks document.images and (b) the DOM write that sets img.alt on the matching element. No static content scripts.
  • sidePanel. Opens the side panel where the LanguageModel runs. The Chrome Prompt API is unavailable in the service worker per Chrome's documented API surface.
  • storage. Persists user preferences (audit toggle, badge toggle, save-history toggle, prompt templates). No image bytes or generated text stored by default.

What we never request

AltGenie never requests host_permissions, tabs, webRequest, declarativeNetRequest, notifications, clipboardWrite (not needed — navigator.clipboard works without it in extension context), identity, <all_urls> (in matches), optional_host_permissions, or alarms.

What we read

When you right-click an image, AltGenie reads the image URL and — for same-origin or CORS-friendly URLs — fetches the image bytes in the side panel context to construct a LanguageModel.ImagePart. For cross-origin images without CORS, AltGenie shows an honest "Cannot read cross-origin image without CORS" message and offers the Copy-URL fallback. No host_permissions is ever requested to bypass CORS.

When you opt in to the passive auto-audit badge, the audit walker reads document.images on the current tab to count those with missing or empty alt. The walker returns a serializable summary (src, dimensions, viewport visibility). It never reads or transmits image bytes; it never writes to the DOM beyond stamping a data-altgenie-id attribute for later write-back.

What we store

  • storage.local. Your settings (audit toggle, badge toggle, save-history toggle, prompt templates), license state (only if you have Pro), and a rolling 100-event funnel log kept only on this device, never sent anywhere.
  • storage.session. The currently-pending image URL between context-menu click and side-panel processing. Cleared when the browser restarts.

AltGenie does NOT persist image bytes or generated alt text by default (per the SPEC privacy contract). The optional save-history feature (opt-in, Pro tier) stores the last 100 generated text items locally — only the text, never the image bytes.

What we transmit

Nothing, by default. The extension makes zero network requests during normal alt-text generation. The only network request the extension ever makes is a POST to the Zovo license Edge Function when you enter a license key in Options or in the popup. The request body is your license key and the extension's product ID. No page content, no image bytes, no browsing history, and no profile data is ever sent. If you never enter a license key, the extension never opens a network connection.

The on-device Prompt API (Chrome's built-in LanguageModel) executes entirely inside the browser process. Image bytes handed to LanguageModel.ImagePart stay on this device.

Your choices

You can toggle auto-audit and the badge from the popup. You can enable or disable save-history in Options. You can delete all local data from the Privacy section of Options. Uninstalling the extension deletes all local data.
